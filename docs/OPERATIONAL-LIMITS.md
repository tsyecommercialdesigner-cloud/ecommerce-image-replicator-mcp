# 运行限制全面检查（v0.1.3，已发布）

检查范围：Settings与CLI默认值、RunOptions、输入冻结、分析/绘图/评审、下载、轮询、修订谱系和任务路由。
新资源标识 `operational_limit_policy=opt-in-v1`。null表示未启用相应应用层限制，不能解释为配置缺失。

| 检查项 | 旧默认 | 新默认 | 显式配置入口 |
|---|---|---|---|
| 分析批次图数/请求字节/输出token | 0并阻止执行 | null，不限制；省略max_tokens | --max-batch-images / --max-request-bytes / --max-output-tokens |
| 输入文件大小（含brief/增量文件） | 50 MiB | null，不限制 | --max-input-bytes，正整数字节 |
| 输入图片像素 | 4000万像素 | null，不限制 | --max-input-pixels，正整数 |
| brief总长度 | 10万字符 | 取消任意字符上限 | 可用max-input-bytes限制单文件体量 |
| 下载大小（URL及Base64） | 50 MiB | null，不限制 | --max-download-bytes，正整数字节 |
| 下载域名名单 | 两个固定域名 | null，不按域名名单限制 | --download-host，重复传入，指定后只接受所列域名 |
| 每次执行轮询截止 | 300秒 | null，无时间截止 | --poll-timeout，正整数秒 |
| HTTP请求各阶段超时 | 180秒，连接20秒 | null，无应用层超时 | --http-timeout，正整数秒 |
| 同工作区图像任务并发上限 | 2，最大8 | null，不限并发任务数 | prepare_run.options.concurrency，正整数，无固定8上限 |
| 每图修订谱系额度 | 0，最大5 | null，不限制 | max_visual_revisions，非负整数；显式0仍禁止修订，无固定5上限 |
| 旧v1导入修订额度 | 0 | null，不限制 | prepare_revision.legacy_revision_budget，同上 |
| 文案/说明/事实/证据长度 | 多处200–16000字符硬上限 | 取消任意业务文本长度上限 | 可通过输入字节/请求字节限制整体体量 |
| 工作区允许根 | 未传已不限制根目录集合 | 保持按需启用 | --allow-workspace-root |

各限制独立生效，不要求先配置才能运行。修改启动项需重启当前Host管理的实际服务并复读资源；任务级限制在准备时冻结。
已有任务保持原run_id与receipt；旧任务中已保存的并发值、修订0额度及谱系上限继续有效，不通过升级静默撤销既有显式/持久化限制。新任务缺省使用null。
默认不限额不代表无限自动生成：视觉修订仍需明确调用准备和执行，生成仍需费用授权、有效凭据。

## 保留的校验与失败处理

这些不是要求业务人员补数值的启动限额，不通过“不限制”跳过：

- HTTPS、禁止URL内凭据、端口443、DNS解析必须为公网地址，不携带API密钥下载，拒绝自动重定向。
- 工作区显式绑定、路径越界/符号链接拒绝、同工作区单执行锁、数据库/产物哈希与任务身份校验。
- 实际图片编码/单帧检查、供应商画布4096/比例/16倍数等技术约束。
- JSON/schema类型、必填/枚举、坐标归一化和边界、禁止结构性改图等契约要求。
- 用户费用授权、有效凭据、未知提交先核查原task_id，不能因放开额度重复POST。
- 有限自动重试（LLM 3+3、绘图最多3次、下载/查询故障3次、视觉评审一次）保留为错误处理策略；不是要求先显式配置的运行门禁，也不扩展为无限自动收费重试。供应商失败和网络错误仍可能返回blocked，需按原任务状态处理。
- 原图/产物必须可访问、输入目录存在、运行账号拥有权限；默认放开配置不等于提升账号权限或绕过操作系统拒绝。

Host自身的工具超时、供应商限额及机器资源仍可能限制执行；本次不修改成员真实Host配置。
旧版v0.1.2不包含新策略，不能仅复制新指南就声称旧进程已放开限制。已发布标签和附件保持原样。
